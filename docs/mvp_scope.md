# MVP Scope and API Compatibility Target

This repository provides an OpenAI-compatible HTTP server for
[Irodori-TTS-MLX](https://github.com/t0yohei/Irodori-TTS-MLX). The public MVP
is the local Apple Silicon MLX server surface that is implemented here, not a
broader clone of upstream Irodori-TTS-Server.

## MVP Goal

Deliver a local server that accepts OpenAI-compatible speech synthesis requests,
returns audio generated by Irodori-TTS-MLX, and exposes enough local operational
surface for real Apple Silicon use.

The public MVP targets:

- API endpoints: `GET /health`, `GET /v1/models`, `POST /v1/audio/speech`,
  and managed reference voice CRUD under `/v1/audio/voices`.
- Runtime backend: Irodori-TTS-MLX with hosted or local model artifacts.
- Initial model path: VoiceDesign v2 no-reference/caption generation.
- Output path: whole-response audio bytes for a completed request.
- Local operation: optional bearer auth, conservative synthesis queueing,
  launchd-oriented deployment templates, and health metadata.

## API Compatibility Target

The server should accept the OpenAI speech request shape where it maps cleanly to
Irodori-TTS-MLX:

| Field | Required | MVP behavior |
| --- | --- | --- |
| `model` | Yes | Selects the configured Irodori-TTS-MLX model family or alias. |
| `input` | Yes | Text to synthesize. |
| `voice` | Yes | VoiceDesign voice or preset identifier. |
| `response_format` | No | Defaults to `mp3` for OpenAI API compatibility. `wav` and raw `pcm` work without optional encoders; `mp3`, `flac`, `opus`, and `aac` require FFmpeg. |
| `speed` | No | Accepted for compatibility and mapped to `duration_scale=1/speed` when `duration_scale` is omitted. |

The MVP response should be an audio byte stream with an appropriate
`Content-Type`. OpenAI-compatible clients that omit `response_format` use the
OpenAI default behavior (`mp3`) when FFmpeg is available. Local smoke tests can
request `response_format=wav` or `response_format=pcm` to avoid optional
encoders. Structured JSON error responses should be used for validation,
missing encoder support, and runtime failures.

Managed reference voice files are intentionally a small safe subset of the
upstream voice API. The server stores uploads under `IRODORI_SERVER_VOICES_DIR`,
accepts common audio upload extensions, resolves managed voice ids into
`irodori.ref_wav`, and rejects arbitrary local paths, path traversal,
remote URLs, symlinks, and latent `.pt`/`.pth` references.

## Non-Goals

The public MVP does not include:

- Model-token or sample-level streaming synthesis on the OpenAI-compatible
  `/v1/audio/speech` route. Chunk-level SSE is available through the separate
  Irodori-specific `/v1/audio/speech/stream-chunks` extension.
- Dynamic LoRA loading or training controls.
- Multi-worker scheduling or horizontal scaling beyond the local synthesis
  semaphore.
- Full parity with every upstream Irodori-TTS-Server route.
- Arbitrary local reference paths, remote reference URLs, voice alias files, or
  latent reference files.
- Docker/CUDA/PyTorch deployment for the upstream server stack.

## First Implementation Boundary

Implementation and follow-up work should keep these assumptions:

1. Runtime integration should stay behind a narrow adapter so request validation
   and response formatting can be tested without loading model weights.
2. Optional production controls should remain local-first: bearer auth, synthesis
   queueing, health checks, and launchd templates rather than a broad deployment
   platform.
3. Compatibility expansion should be explicit. Unsupported upstream options are
   rejected with stable OpenAI-style errors instead of being silently ignored.
4. Public docs should describe the implemented Apple Silicon MLX boundary and
   point broader upstream needs back to Aratako/Irodori-TTS-Server.
